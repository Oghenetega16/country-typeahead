# Write-up — Country Search Typeahead

**Tradeoffs.** I originally built this against the REST Countries API, but that endpoint was deprecated by its provider during this task — it now requires a signed-up API key, which isn't appropriate to embed in browser code. I moved the search to the Open-Meteo Geocoding API instead: free, keyless, CORS-enabled, and actively maintained. I split the code into three thin layers — API client, a behavior hook (debounce/stale-request/keyboard state), and presentation — but stopped short of full "Clean Architecture" layering (entities, use-cases, repositories): that's more indirection than a single component needs, and matching structure to scope felt more useful than maximal layering. For debouncing I used a `useEffect` + `setTimeout` hook rather than a library, since the effect's cleanup already gives correct cancel-on-rerender behavior for free. For stale responses I combined an `AbortController` (cancels the in-flight fetch) with a monotonically increasing request-id ref as a backup guard, since some environments silently swallow abort errors. I skipped a request cache to keep the component small, though it's the natural next addition.

**Scaling / hardening for high traffic.** I'd add: (1) a client-side LRU cache keyed by trimmed query, so retyping doesn't refire requests; (2) a slightly longer debounce (300–400ms) plus the existing 2-character minimum to cut request volume; (3) a thin proxy/edge function server-side in front of the third-party API for caching headers, per-IP rate limiting, and hiding any future API key; (4) `stale-while-revalidate` semantics so the last good list stays visible while a new request resolves, rather than flashing a loading state.

**Testing.** Unit tests (Vitest/RTL) for the debounce hook and the stale-response guard — resolve an earlier mocked fetch after a later one and assert the earlier result never renders. Integration tests for keyboard nav (wraps, Enter selects, Escape closes) and loading/empty/error rendering, using MSW to mock a deliberately slow first response.
